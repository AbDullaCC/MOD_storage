# Operations log

**سجل العمليات** (`/audits`) is the single admin page for stock movements, edits, cancellations, archiving, and restoration. It replaces the separate reports, central audit, and per-item history pages. From item details, the same page opens with `product_in_id` already selected. `/storage/report` redirects to the full log, and `/storage/item/{id}/history` redirects to the item-filtered log. Operators and disabled accounts cannot access the page, redirects, or export.

The page shows the newest entries first, 20 per page, in a table with prominent item names, plain-language actions, quantities, source/destination or changed fields, stock before/after, actor, and recording time. Green indicates stock increases and red decreases, including the reversed stock effects of cancellations; descriptive edits use amber. Legacy cancelled movements are muted and never imply a saved balance change. On smaller screens, each table row stacks its fields without horizontal page scrolling. The details button expands operation data and any reason underneath its row. Clicking an item name opens the exact same full item card as the inventory page, including additions, withdrawals, cancellation history, and admin correction controls. Both pages include `storage.partials.item-card`, `operation-dialogs`, and `inventory-dialog-scripts`, so markup, behavior, and styling stay shared. The card details use larger labels with a restrained green accent and smaller neutral values. Stock is labelled **المخزون**, with a blue label (red when empty), and displays only its number below. The read-only `/audits/items/{product}` JSON endpoint requires an active admin, returns current item data and movements ordered by operation date, and disables caching. Text fields are inserted as text or escaped before rendering. The card closes with Escape, its close button, or a backdrop click, returns focus to the item link, and opens corrections as stacked dialogs that return to the same card. Its **سجل العمليات** button opens the item-filtered log. Filters are collapsed by default and open automatically when a filter is active. Selecting an item in the filters shows its current balance and status; if archived, the reason-required restoration form is available there. The inventory list still has its separate current-stock CSV export.

## Filters and dates

Combine user, item, record type, action, and recording date range. Both endpoints include their whole day in the configured application timezone (Asia/Damascus); either endpoint can be omitted. Pagination preserves filters, and clearing filters restores the full list. **المستخدم غير معروف** selects legacy rows with no recorded creator. Disabled users and archived items remain selectable.

Saved audit entries use their server recording time and the actor name saved then, displayed in the main row. The rightmost column describes what happened, followed by the item; headers and values align right. Unchanged stock shows **دون تغيير**, with no duplicate balance values in the row or details. Details use neutral backgrounds, subtle separators, clear labels, and bold values for business data (quantity, source/destination, notes, and item fields), stock impact only when it changes, and any reason. Withdrawal/addition details omit the **ما الذي تغيّر؟** section; their edit summaries remain visible in the main row. Item edits and archiving/restoration retain meaningful comparisons, with status labels instead of internal timestamps. Internal IDs, creator/cancellation metadata, and system dates are hidden from operation details; complete snapshots remain stored and exported. The entered operation date is shown once as a date in the details, outside comparisons; CSV retains the full value. Legacy operations use their original `created_at` where available, with the entered operation date as the fallback if no recording timestamp exists. Names/usernames in the user filter and item links are current; saved audit field values retain their historical contents.

## Older operations

`OperationLog` combines the existing audit table with read-only rows from items, additions, and withdrawals that have no matching creation audit entry. New operations with a creation audit entry are not duplicated. No records are inserted or rewritten, and no database migration is required.

Legacy rows are labelled **سجل سابق** and show current stored operation fields, any saved original creator, and cancellation metadata if present. They have no invented audit ID, historical stock balances, or before/after snapshots. Later edits and cancellations still appear as distinct saved audit events with their actual comparisons and reasons.

## Export

**تصدير النتائج CSV** exports all matching rows, independent of the visible page. The screen and export share filtering and validation. CSV is streamed in batches, uses UTF-8 with a BOM for Arabic spreadsheet compatibility, and includes identities, actor, dates, quantities, source/destination, notes, reason, stock balances/delta, and JSON field values.

The final **مصدر البيانات** column distinguishes saved audit snapshots from legacy current-state data. Legacy audit ID, before snapshot, and historical balances are empty; legacy JSON contains only current operation fields. Spreadsheet formula-like text is prefixed with an apostrophe in the export without changing stored data.
